# 合作方尽调 · 完整流程 v2（含域名遗产尽调）

> 适用：亚马逊站外推广（联盟客 / 红人）合作方筛查与体检
> 引擎：claude-seo（v2.2.4 内置）+ 自研 batch_analyzer 工具链
> 更新：2026-09-03

---

## 一、一句话总览

一条流水线把"一堆网址"变成"可放心联系的合作方名单"：
**初筛（活没活）→ 四维体检（A/B/C/D）→ PageRank 权重 → 域名遗产尽调（防灰产套壳）→ 主题漂移复查（高风险二查）→ 分级打标 → 推飞书开联系**。

其中**域名遗产尽调是 v2 新增的第 4 关**，堵住前面体检抓不到的灰产套路。

## 二、v2 新增：域名遗产尽调（domain_age_scan）

### 2.1 为什么加这一关

前面 3 关（初筛/四维体检/PageRank）判断的是"这个站现在好不好"，**判断不了"这个域名是不是灰产套壳"**：

SEO 灰产标准打法 = 抢注/收购**注册多年**的老域名 → 不保留原主题 → 批量改成 coupon / 折扣 / 黑五站。老域名天然带年龄权重和历史外链，能骗过 PageRank 和内容体检，却是 Google 质量评估准则（QRG §4.6.7）明确打击的对象。**合作方主站若是这种货，我们挂的联盟链接会被连带降权。**

注册年龄是这道尽调的第一硬信号——正规联盟客站点极少用"刚注册不到 2 年的新域名"。

### 2.2 工具：tools/domain_age_scan.py

- **输入**：台账 CSV（含"域名"列）或每行一个域名的 txt
- **主通道**：系统 whois（复用上游 `domain_history.py` 的解析）
- **兜底通道**：RDAP over HTTPS（Verisign 直连 / rdap.org 聚合）——whois 43 端口被限时自动切换
- **输出列**：域名 | 注册日期 | 注册年限 | 到期日 | 注册商 | 来源(whois/rdap) | 年龄带

```bash
python tools/domain_age_scan.py --csv 合作方台账.csv -o 域名遗产尽调_年龄扫描.csv
python tools/domain_age_scan.py --domains 名单.txt --workers 10 -o out.csv
```

- 纯标准库 + 系统 whois，**无新增 Python 依赖**（tldextract 已在 requirements）
- 并发默认 8，~1000 域名约 5 分钟

### 2.3 年龄带怎么读

| 年龄带 | 含义 | 尽调动作 |
|---|---|---|
| 新壳 <2 年 | 域名刚注册，正规联盟客几乎不用 | **重点关注**：结合体检/内容质量判断是否黑五站，评分降档或直接剔除 |
| 年轻 2-5 年 | 中途换手常见区 | 结合内容质量 + 外链判断 |
| 中年 5-10 年 | 相对可信 | 正常联系 |
| 老域 10 年+ | 年龄权重高 | ⚠️ 若内容主题与"历史用途"不符 = 灰产套壳高危，**必须走 2.4 主题复查** |

### 2.4 主题漂移复查（第二阶段，Wayback）

单跑年龄扫描只能拿到硬信号，判断"内容主题是否被换过"需要对比历史：
1. 对 老域10年+ 与 新壳<2年 两个高风险段的域名
2. 抓 **Wayback Machine 最早快照**（`https://archive.org/wayback/available?url=域名&timestamp=最早`，免费 API）
3. 与当前首页做关键词主题对比 → 输出 topical_shift
4. 叠加上游 `domain_history.py` 的 `assess_risk` 规则：<2年+已变 / ≥5年+已变 → **high**；2~5年+已变 → medium

> 上游脚本本身不做 Wayback 对比（作者在注释中明说委派给 seo-content skill），批量版需自接 archive.org API。

**自动化工具**：`tools/topic_shift_check.py`（CDX 查最早快照 → trafilatura 提取正文 → 关键词集相似度 → 自动评级）。⚠️ **依赖能访问 web.archive.org 的网络**——在受限网络下无法运行，此时改用人工复查包（见第五节）。

```bash
python tools/topic_shift_check.py --csv 合作方台账_v2.csv --only-band "老域(10年+)" -o 主题复查结果.csv
python tools/topic_shift_check.py --csv 合作方台账_v2.csv --domains 名单.txt -o 结果.csv
```

## 三、全功能盘点：claude-seo 对我们数据还能做什么

对照基准：台账现有 34 列已含 体检四维评分 / 分级 / PageRank / 外链主机数 / 目标国家·语言 / 信任页 / robots·sitemap / 内容质量·AI 信号 / 标题·meta·canonical / 邮箱 / 联系状态。

### 3.1 ✅ A 类：免费、无 key、贴合业务（推荐封装）

| 能力 | 脚本 | 对我们数据/业务的用处 | 消费什么 |
|---|---|---|---|
| **域名遗产尽调** | `domain_history`（已封装为 domain_age_scan） | 防灰产套壳，尽调第 4 关 | 台账"域名"列 |
| **寄生 SEO 风险** | `parasite_risk` | 判断合作方主站放我们的链接/内容会不会被 Google 当"寄生页"打击 | 台账 A/B 级候选 URL |
| **找投放位** | `sitemap_discovery` | 挖重点合作方站点的 `/coupons` `/deals` 目录页，规划具体投放位 | 已合作/重点候选 URL |
| **稿件事实核查** | `content_verify` | 红人/联盟客交回的稿子，把"张口就来"的数据引用挑出来 | 稿件文本（非台账） |
| **正文低质检测** | `content_quality` | 单篇稿件质量把关（工具1已内置粗版） | 稿件文本 |

### 3.2 🟡 B 类：免费申请 key 后可用（可选补充）

| 能力 | 脚本 | 用处 | 门槛 |
|---|---|---|---|
| **YouTube 频道/视频数据** | `youtube_search` | 红人开发线：拉频道订阅数、视频表现、判断红人量级（补上你自建 KOL 评分的关键数据源） | Google API key（免费） |
| **真实用户性能 CrUX** | `crux_history` / `lcp_subparts` | 给重点合作方补"手机端真实性能"维度——现在台账"移动适配"只有布尔值 | CrUX API key（免费） |
| **Pagespeed 实验室分** | `pagespeed_check` | 同上，Lighthouse 分数 | API key |
| **语义/情感分析** | `nlp_analyze` | 对合作方首页正文做实体/情感分析，丰富"正文质量"判断 | Google Cloud NL key |

### 3.3 🔴 C 类：需付费订阅（暂不碰）

`moz_api`（Moz 付费）· `dataforseo_*`（DataForSEO 付费）· `keyword_planner`（Google Ads 广告账户）
——这些提供的是我们已有替代品的付费数据（权威分/关键词量），不划算。

### 3.4 ⚪ D 类：自家品牌站向（非合作方尽调，Stouchi 自站 SEO 时再用）

| 组 | 脚本 | 场景 |
|---|---|---|
| 搜索控制台 | `gsc_inspect` `gsc_query` `google_report` `bing_webmaster` | 自家站收录/排名监控 |
| GA4 | `ga4_report` | 自家站流量分析 |
| 收录提交 | `indexnow_submit` `indexing_notify` | 自家站新页提交 |
| SEO 漂移监控 | `drift_*` `consistency_check` | 监控自家站页面是否被改坏 |
| Schema | `schema_generate` `schema_ecommerce_validate` | 自家站结构化数据 |
| 渲染/截图 | `render_page` `capture_screenshot` `analyze_visual` `agent_ux_check` | 需要 Playwright，人工看合作方页面时可选 |
| 内容人性化 | `content_humanize` | 写外联文案去 AI 味 |
| 其它内部件 | `seo_updates` `preload_check` `ucp_check` `gbp_deprecation_lint` `iptc_ai_label` `portability_check` `release_sign` `verify_release` `sync_flow` `runtime` `backlinks_auth` `verify_backlinks` `validate_backlink_report` `unlighthouse_run` `google_auth` | 上游自用/自家站审计，与我们数据无直接关系 |

### 3.5 结论

- 对"现有台账 998 行"这个数据资产，claude-seo 的边际增量集中在 **3 个免费方向**：寄生风险（parasite_risk）、投放位挖掘（sitemap_discovery）、**域名遗产（已落地）**。
- 给红人线补数据源的话优先 **youtube_search**（免费 key）。
- 其余 40+ 脚本多数面向"自家品牌站 SEO"，等 Stouchi 自站做 SEO 时才是主战场。

## 四、完整流程（7 关 + 复检）

### 阶段总览

| 关 | 动作 | 工具 | 输入 → 输出 | 谁执行 | 耗时 |
|---|---|---|---|---|---|
| 0 | 名单入库 | Excel / 多市场候选 | 原始名单/候选池 → 待筛 URL 清单 | 人工收集 | — |
| 1 | **批量初筛** | `batch_site_analyzer` | URL 清单 → 有效/无效 + 语言·国家·标题 | AI/同事 | ~千条/小时 |
| 2 | **四维体检** | `partner_health_check` | 有效站点 → 运营20+技术35+内容45 评分 + A/B/C/D | AI/同事 | ~千条/小时 |
| 3 | **权重扫描** | `cc_batch_scan` | A/B 级域名 → PageRank + 外链主机数 | AI | ~700 域/分钟 |
| 4 | **域名遗产尽调** | `domain_age_scan`（新增） | 全部唯一域名 → 注册年限/到期/注册商/年龄带 | AI/同事 | ~1000 域/5 分钟 |
| 5 | **主题漂移复查** | Wayback API + `domain_history.assess_risk` | 老域10年+/新壳<2年 高危段 → topical_shift + high/medium/low | AI | 高危段样本量 |
| 6 | **打标汇总** | pandas/Excel | 全字段合并 → 分级修正 + 备注 + 风险标记 → 推飞书 Base | AI | 分钟级 |
| 7 | **联系管理** | 飞书多维表格 | 台账记录 → 待联系/已联系/已回复/合作中/已拒绝 + 备注 | 专员 | 持续 |

### 关卡插桩规则

```
0 名单入库
   │
   ▼
1 初筛 ──无效──► 剔除归档
   │ 有效
   ▼
2 四维体检（运营20/技术35/内容45 → A/B/C/D）
   │
   ▼
3 PageRank + 外链主机数（A/B 级优先）
   │
   ▼
4 域名遗产尽调 ◄── 全部唯一域名
   │
   ├─ 新壳<2年 ─► 标"关注"：结合内容质量复核，倾向降档
   ├─ 老域10年+ ─► 进第 5 关主题复查
   │
   ▼
5 主题漂移复查（Wayback 最早快照 vs 当前首页）
   │  shifted & (≥5年 or <2年) → HIGH 灰产套壳 → 剔除/拉黑
   │  shifted & 2~5年      → MEDIUM → 降档观察
   │  无 shift             → LOW → 放行
   ▼
6 打标汇总 → 修正分级 → 新增列：注册日期/年限/到期/注册商/年龄带/域名风险
   ▼
7 推飞书多维表格 → 按合作优先级联系 → 回填联系状态/备注
```

### 复检周期

| 周期 | 动作 |
|---|---|
| 每轮新名单 | 全流程 0-7 |
| 每月 | 对"待联系/已联系"新增量跑 2-4 关（体检变化 + 域名新增） |
| 每季 | 全量复跑 2-4 关，比对分级漂移（A↔D 变化榜单） |
| 不定期 | 重点候选上新功能（寄生风险/投放位挖掘）时补跑 |

### 质量门槛（建议）

| 指标 | 标准 |
|---|---|
| 初筛抓取成功率 | ≥90%（低于则检查网络/代理） |
| 体检覆盖 | 有效站点 100% 覆盖 |
| PageRank 命中 | 本地索引命中率作为参考（中欧域名偏低正常） |
| 域名扫描成功率 | ≥95%（whois+RDAP 双通道） |
| 飞书落库 | 记录数与本地台账一致，无重复（按 URL 去重） |

## 五、本次对台账的实测结果（2026-09-03）

对 `合作方台账_US_DE_汇总.csv`（998 行）全量跑第 4 关：

- **扫描规模**：984 个唯一注册域 · 891 个取得注册日期（**90.5%**）· 耗时 **2 分 43 秒**（RDAP 主通道，12 并发）
- **未取得 93 个**：`.de` 域名 32 个（DENIC 按 GDPR 不公开注册日期，whois/RDAP/web 全不可查，属正常限制）+ 其它 61 个（新 gTLD / 注册局屏蔽）

### 年龄带分布（全台账）

| 年龄带 | 数量 | 占比 | 说明 |
|---|---|---|---|
| 新壳 <2 年 | **283** | 28.4% | 2024-09 后注册 —— 高于预期，需重点复核 |
| 年轻 2-5 年 | 267 | 26.8% | 常规 |
| 中年 5-10 年 | 174 | 17.4% | 常规 |
| 老域 10 年+ | 180 | 18.0% | 年龄权重高 |
| 未知 | 94 | 9.4% | .de 隐私 32 + 注册局屏蔽 62 |

### ⚠️ 关键发现：A/B 级里混着 191 个"新壳"域名

| 分级 | 新壳<2年 | 占总新壳 |
|---|---|---|
| A | 76 | 26.9% |
| B | **115** | 40.6% |
| C | 67 | 23.7% |
| D | 25 | 8.8% |

**含义**：优先联系清单里评分高、但域名 2024 年后才注册的站点有 191 个（如 A 级 88.2 分的 lateralthinkingpuzzles.org 注册于 2025-06、tangwen.org 注册于 2025-09）。新域名 ≠ 灰产（新站起步很正常），但 coupon/折扣向站点大量使用新壳域名是常见灰产特征——**这 191 个建议在联系前做一次人工内容复核**（看是否有真实运营痕迹、社交/收录历史），体检分只能证明"站做得像样"。

### 交付文件

- `合作方台账_US_DE_汇总_v2_含域名尽调.csv` —— 主台账新增 6 列：注册日期/注册年限/到期日/注册商/来源/年龄带
- `域名遗产尽调_年龄扫描.csv` —— 扫描原始结果（984 域）
- `重点关注_新壳域名AB级.csv`（191）—— 联系前复核清单
- `套壳嫌疑_老域名CD级.csv`（30）—— 老域名+低质量，Wayback 主题复查优先样本
- `优质候选_老域名AB级.csv`（150）—— 老域名+高质量，最稳妥的优先联系对象
- `人工复查_老域名套壳嫌疑30.csv` —— 第 5 关人工版：30 行嫌疑域名附 Wayback 核对链接（当前运行环境无法访问 archive.org 时的替代路径；网络恢复后可用 `tools/topic_shift_check.py` 一键自动化）

> ⚠️ 复查提示：30 个嫌疑样本是"老域名×低质量"的粗筛结果，其中混有正常老站被评低分的情况（如老牌站点可能因体检的运营/技术维度扣分），也混有 `github.io`/`substack.com` 子域等噪声——人工核对时以"历史快照内容 vs 现在内容是否同主题"为准，不要只看分级。
